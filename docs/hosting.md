# Публичный сервер

Тестовый сайт: **https://webmtv.b020207d.sslip.io**. Бесплатный DNS sslip.io указывает на статичный IP; сертификат Let's Encrypt автоматически продлевается. Это внешний DNS-сервис без нашего SLA. В адресе используется шестнадцатеричная запись IP: это убирает явные цифры из ссылки, но не скрывает IP от DNS-проверки. Старый адрес перенаправляется на новый. Короткий собственный домен можно подключить позднее.

## Как устроено

Ubuntu → nginx (HTTPS, статика, кеш GET, ограничения) → Node.js на `127.0.0.1:4173`. Видео браузер получает непосредственно с Двача; VPS хранит только общий индекс метаданных. Публичный API отдаёт общие кешируемые порции до 96 роликов. Очередь браузера ограничена 400 роликами; следующая порция нужна, когда осталось меньше 24 непросмотренных кандидатов. История и предпочтения остаются в браузере.

`PUBLIC_ORIGIN` включает публичный режим. Он отключает `/api/shutdown` и старые задания `/api/feeds`, не выдаёт токен выключения или адреса локальной сети. Без этой переменной домашний запуск работает как раньше.

Один общий обход источника обновляет индекс при открытом приложении. Готовые JSON-ответы кешируются до минуты; nginx и браузер используют Cache-Control и ETag. Дерево обновляется примерно раз в минуту; пустая выдача повторно проверяется быстрее. Индекс записывается атомарно не чаще раза в минуту. `data/` не входит в релиз.

## Обновление и откат

Push в `main` запускает `.github/workflows/check.yml`: тесты, сборка, проверка локального запуска и публичного режима на трёх ОС. Только после успеха Linux runner собирает архив и передаёт серверу.

SSH-ключ GitHub принадлежит отдельному пользователю `webmtv-deploy`. Он разрешает только приём архива, без терминала и туннелей. Установщик проверяет размер и содержимое, запрещает ссылки и выход из каталога, переключает `current` на новую версию и сверяет SHA через health endpoint. При неудачном старте возвращает предыдущую версию. Хранятся три последних релиза и текущая/предыдущая версии.

Секреты репозитория: `WEBMTV_DEPLOY_KEY`, `WEBMTV_KNOWN_HOSTS`. Приватных ключей в репозитории нет. Настройки nginx, systemd и firewall находятся в `deploy/`; их изменения устанавливаются администратором отдельно от кода приложения.

На сервере:

```sh
systemctl status webmtv nginx
journalctl -u webmtv -n 100
curl http://127.0.0.1:4173/api/health
ls /srv/webmtv/releases
```

Для ручного отката выберите существующий SHA:

```sh
ln -sfn /srv/webmtv/releases/SHA /srv/webmtv/current
systemctl restart webmtv
curl http://127.0.0.1:4173/api/health
```

## Доступность и лимиты

- systemd перезапускает упавшее приложение. Таймер каждую минуту проверяет HTTP и перезапускает после трёх подряд неудач.
- GitHub Actions проверяет публичные HTTPS и API примерно каждые 15 минут. Расписание может задерживаться; уведомления о провале зависят от настроек GitHub владельца. После 60 дней без активности GitHub может отключить расписание публичного репозитория.
- Приложение ограничено 512 МиБ RAM, 256 МиБ swap и 75% одного CPU. Amnezia AWG и DNS сохранены отдельно.
- nginx ограничивает API до 5 запросов/с с одного IP и 30/с суммарно, с небольшими допусками для всплеска. Максимум 16 активных соединений на IP и 160 на сайт; перегрузка возвращает 429. У клиентов за одним NAT общий лимит.
- SSH принимает только ключи; вход по паролю отключён.
- Firewall оставляет SSH, HTTP/HTTPS и порт Amnezia; Docker forwarding не меняется. Ограничен темп новых TCP-соединений к веб-портам.
- Запросы и их тела ограничены по размеру и времени. Каталог, кеш, журналы и число релизов ограничены; ежедневные сжатые снимки индекса хранятся несколько дней.

Это защита приложения от лишней нагрузки, **не защита от объёмного DDoS**: IP открыт, поток выше пропускной способности канала может сделать недоступными и сайт, и VPN. sslip.io предоставляет DNS, а не анти-DDoS-прокси. Платные сервисы не подключены.

Снимки индекса находятся на том же VPS (`/var/backups/webmtv`) и не спасут при его потере. Индекс можно собрать заново из источника; пользовательских аккаунтов или серверной истории нет. Проверки не гарантируют доступность чужих видео: удалённый файл или недоступный Двач приложение восстановить не может.

## Первичная установка на другой VPS

1. Установить Node.js 22.12+ в `/opt/webmtv-node`, nginx, certbot, Python 3, sudo.
2. Создать пользователей `webmtv` и `webmtv-deploy`; `/var/lib/webmtv/data` принадлежит первому, `/srv/webmtv` — второму.
3. Задать `PUBLIC_ORIGIN=https://ваш-адрес` в `/etc/webmtv.env`. Получить сертификат, заменить `DOMAIN` в `deploy/nginx.conf`. Продление certbot использует `/var/www/letsencrypt` и deploy-hook `systemctl reload nginx`.
4. Установить `deploy/activate.py` как root-owned `/usr/local/bin/webmtv-deploy`, разрешить deploy-пользователю в sudoers только `systemctl restart webmtv.service`. В authorized_keys использовать `restrict,command="/usr/local/bin/webmtv-deploy"`.
5. Установить systemd units и соответствующие скрипты из `deploy/`. **Перед применением firewall проверить порты своего SSH/VPN**: текущая конфигурация рассчитана на этот VPS.
6. Изменить адреса в GitHub workflows, добавить deployment secrets, запустить Check. Включить таймеры мониторинга, резервирования и certbot.

Проверки запуска используют `WEBMTV_DATA_DIR` с временным каталогом, чтобы не менять рабочий индекс. Сервер начинает принимать запросы только после чтения индекса; выключение также дожидается чтения перед записью.

Подробности общей выдачи и измерения: [оптимизация многопользовательского режима](performance.md). История просмотров больше не передаётся при загрузке порций: пользовательская фильтрация выполняется в браузере.
